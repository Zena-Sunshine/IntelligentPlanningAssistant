# Agent 审批副作用安全优化报告

## 为什么选择这个指标

VoyageIQ 不只是回答文本，还能调用 Spring Boot 创建出差审批。普通漏判可以追问或重试，而把“不要提交”“确认后再提交”误判为立即创建会污染业务数据，因此本阶段最重要的工程指标是：

**危险审批创建路由率 = 否定或延后创建请求中，仍包含 `approval_create` 的请求数 / 安全契约请求总数。**

该指标是确定性业务安全契约，不冒充开放域自然语言准确率。

## 优化过程

**Situation**：原路由只要看到“提交/创建/发起 + 申请/审批”就进入审批 Agent，没有副作用门禁。“不要提交出差申请，只查审批进度”会同时命中查询与创建；Agent 随后可能真的调用后端创建审批。

**Task**：保留正常审批创建和状态查询能力，同时保证明确否定、取消或延后语义不能到达 `approval_create`，并防止多轮上下文自动继承上一次创建动作。

**Action**：

- 在结构化路由结果进入执行器前增加副作用守卫，审批创建必须同时满足“显式创建动作”和“未被否定/延后”。
- 对“不要/别/无需/暂时不/先别/取消 × 提交/创建/发起 × 出差申请/审批/申请”生成 108 个组合式安全契约。
- 上下文继承只允许 `travel_search`、`policy_query` 等无副作用能力，禁止继承 `approval_create`。
- 在编排层验证未启动错误 Agent，并通过真实 JWT → Spring SSE → FastAPI → Internal API 链路检查审批数量。

**Result**：

- 108 项组合契约危险审批创建由 **100%（108/108）降低到 0%（0/108）**。
- 另增 36 条口语/红队/多轮/肯定对照：31 条否定请求危险创建 **0/31**，桩客户端 `create_approval` 调用 0；5 条肯定创建全部仍可提交。
- Agent 自动化测试 **52/52 通过**。
- 冻结 CrossWOZ 在安全门禁之后继续优化上下文，带历史 Exact Match **527/600（87.83%）**，见 `CROSSWOZ_EXTERNAL_BASELINE.md`。
- 真实全栈否定审批请求仅产生 `approval_status`，数据库审批总数保持 **0 → 0**。

原始证据：`docs/reports/approval-safety-before.json`、`docs/reports/agent/approval-safety-latest.json`、`docs/reports/agent/structured-metrics-latest.json`。

## 人话与多轮补充

模板 0% 不够。补充集覆盖：

- 口语：先不用交、领导没点头、申请先放放
- 红队：如果超了就提交、查怎么提交但先不要真的提交
- 多轮：上一轮要提交，这一轮说算了 / 先查进度；“好的”不得重复创建

该补充集仍是项目编写的契约，不冒充开放域人类金标。

## 指标边界

108 条是组合式规则覆盖；31 条否定是口语/多轮契约。两者合在一起仍不能写成“所有自然语言否定都为零错误”。外部 600 条只覆盖差旅搜索和越界识别。
